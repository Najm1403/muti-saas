Config Reference

Every field a Business Template's config JSON understands, and how to edit it — for the Business Templates screen.

How this works

Every tenant is onboarded onto exactly one Business Template (Fast Food, Electronics, Laptop Business, ...). The template's config is one JSON object that drives everything about how that tenant's dashboard and POS behave — which fields show on a product form, whether Variant Option Groups exist at all, what the POS layout looks like, and now, which whole dashboard sections (modules) a tenant can see.

To edit a template: go to Business Templates, click an existing card (or "New Template"). Three of the most commonly-changed fields — variants.enabled, addons.enabled, and modules.hidden — have real checkboxes in the editor that stay in sync with the JSON textarea below them. Everything else is edited directly as JSON in that textarea. Click Save; the server re-validates the shape (e.g. rejects an unknown or mandatory module key in modules.hidden) before it's applied — a syntax-valid JSON blob isn't automatically an accepted config.

Nothing is required. Every key below is optional — an absent key falls back to a safe default (usually "on"/"unrestricted"), exactly like modules.hidden defaults to "nothing hidden" when absent. You only need to write the keys you want to change from that default.

Changes apply to every tenant on that template immediately — there is no per-tenant override for any of these settings (a tenant's individual identity — name, branches, users, devices — lives on the Tenant record itself, not here).

pricing

Controls Cost Price visibility. Cost Price is always optional.

FieldTypeDefaultEffect
show_cost_priceboolfalseShows the Cost Price field on the product-creation drawer.
require_cost_priceboolfalseLegacy compatibility key. It is ignored; Cost Price remains optional.
show_compare_priceboolfalseShows a "was" strike-through price alongside the sale price.
 
"pricing": { "show_cost_price": true, "require_cost_price": false, "show_compare_price": false }

variants

Whether this business type uses Variant Option Groups (SKU-defining options like RAM/Storage/Size) at all, and what gets seeded at onboarding.

FieldTypeDefaultEffect
enabledbooltruefalse hides Component Groups/Variants everywhere in the tenant dashboard and blocks attaching one server-side (enforce_variants_enabled) — the business sells one Product priced with delta Add-ons only (e.g. Fast Food).
seed_groupsarray[]Variant Option Groups created automatically at onboarding — [{"name": "RAM", "values": ["4GB","8GB"]}, ...].
max_option_groupsint | nullnullOptional cap on how many groups a product can attach. null = unlimited.
 
"variants": {
  "enabled": true,
  "max_option_groups": null,
  "seed_groups": [
    { "name": "RAM", "values": ["4GB", "8GB", "16GB", "32GB"] },
    { "name": "Storage", "values": ["128GB", "256GB", "512GB", "1TB"] }
  ]
}

addons

Delta-priced Add-ons (Extra Cheese +$1, No Onion, ...) — structurally separate from Variant Option Groups, never generates a combination SKU.

FieldTypeDefaultEffect
enabledbooltruefalse hides the Add-ons section everywhere in the tenant dashboard and blocks attaching an Add-on Group server-side (enforce_addons_enabled) — the business prices everything via Variant Options instead (e.g. Laptops).
seed_groupsarray[]Add-on Groups created at onboarding — each item has name, selection_type ("single"/"multiple"), min_select, max_select, and items (each with name, price_delta, optional default_selected).
 
"addons": {
  "enabled": true,
  "seed_groups": [
    { "name": "Toppings", "selection_type": "multiple", "min_select": 0, "max_select": 5,
      "items": [
        { "name": "Extra Cheese", "price_delta": 100 },
        { "name": "Mushroom", "price_delta": 80 }
      ] }
  ]
}

product_fields

Which optional fields show on the product form — never required, just shown or hidden.

FieldTypeDefaultEffect
skubooltrueShows the SKU field.
specsbooltrueShows the key/value Specifications section.
warrantybooltrueShows the free-text Warranty field.
descriptionbooltrueShows the product Description field.
 
"product_fields": { "sku": true, "specs": true, "warranty": true, "description": true }

pos

Which POS screen layout the Flutter app uses for this business type.

FieldTypeDefaultEffect
layoutstring"grid_with_variant_picker""grid_with_variant_picker" (a side-panel variant/component picker — for businesses with real SKU options, e.g. laptops) or "grid_quick_tap" (instant-add/bottom-sheet — for fast, few-choice menus, e.g. fast food).
 
"pos": { "layout": "grid_with_variant_picker" }

inventory

How strictly stock tracking is enforced for this business type.

FieldTypeDefaultEffect
tracking_editablebooltrueUI metadata indicating that a tenant may edit the tracking choice.
tracking_default_onboolfalseNew products and their variants start tracked when the form does not provide a choice; the tenant can still turn tracking off.
tracking_forced_onboolfalseEvery variant must track inventory — enforced server-side (enforce_tracking_policy), not just a UI default.
low_stock_thresholdinteger5Initial tenant threshold. The tenant can later change it in Settings; alerts only evaluate tracked variants per branch.
 
"inventory": { "tracking_editable": true, "tracking_default_on": true, "tracking_forced_on": false, "low_stock_threshold": 5 }

categories

Categories created automatically at onboarding, so a new tenant isn't staring at an empty Menu.

"categories": { "default_categories": ["Laptops"] }

modules

Which whole dashboard sections this business type's tenants can see at all — Kitchen Stations, Promotions, Reports, and so on. This replaces the old, separate "Module Templates" system: there is no per-tenant override any more, only per-Business-Template.

FieldTypeDefaultEffect
hiddenarray<string>[]Module keys to hide. Absent/empty = every module visible (opt-out, not opt-in). Hiding a module removes it from the tenant dashboard sidebar and blocks its API routes server-side with 403 MODULE_DISABLED — a direct API call can't bypass it. The three mandatory modules (dashboard, subscription, settings) can never be hidden — listing one is rejected when you save.

"modules": { "hidden": ["kitchen", "promotions"] }

In the Business Templates editor this is also a checkbox grid — uncheck a module there and it's synced into this field on Save. Editing the JSON directly works exactly the same.

Changing this — two guards are enforced, not just advice

  • Permission required. Needs can_manage_business_templates (Owners have it implicitly; a Manager needs it granted from Platform Users) — without it the save is rejected before anything runs.
  • Password re-confirmation required, every time. Saving a change to hidden (or deleting the template) opens a "Confirm your password" prompt — a 5-minute token scoped to this exact action and template, even if you already have the permission above.
  • Still applies to every tenant on this template immediately once confirmed — check "View tenants using this template" on the grid first so you know the blast radius; neither guard checks that for you.
  • No warning to the tenant. The sidebar link disappears and the routes start 403ing on their very next request — no grace period.
  • Hiding sales, promotions, or deals reaches the POS, not just the dashboard — hiding sales blocks a cashier session from opening at all (a shop cannot ring up sales); hiding promotions/deals silently drops them from live order pricing.
  • Fully reversible. Nothing is deleted — re-check the box and confirm again to restore instantly (needs its own fresh password step-up too).
  • Verify after saving by checking an affected tenant's dashboard, rather than trusting the checkbox alone.

Full write-up: BUSINESS_TEMPLATE_GUIDE.md, "Changing modules.hidden on a template that's already in use."

Full example

A complete, real config — the "Laptop Business" template, with Kitchen and Promotions hidden (a laptop shop has no kitchen and this one doesn't run promotions).

{
  "pos": { "layout": "grid_with_variant_picker" },
  "addons": { "enabled": true, "seed_groups": [] },
  "pricing": { "show_cost_price": true, "require_cost_price": false, "show_compare_price": false },
  "variants": {
    "enabled": true,
    "max_option_groups": null,
    "seed_groups": [
      { "name": "RAM", "values": ["4GB", "8GB", "16GB", "32GB"] },
      { "name": "Storage", "values": ["128GB", "256GB", "512GB", "1TB"] }
    ]
  },
  "inventory": { "tracking_editable": true, "tracking_default_on": true, "tracking_forced_on": false, "low_stock_threshold": 5 },
  "categories": { "default_categories": ["Laptops"] },
  "product_fields": { "sku": true, "specs": true, "warranty": true, "description": true },
  "modules": { "hidden": ["kitchen", "promotions"] }
}
